# Data verification, 2026-10-11

Every value in `index.html` (devices, purchasable systems, models, rates) was checked against public sources on 11 October 2026. For each field, this log records: our value before the check, the found value, the verdict (confirmed, deviates, uncertain, not found), the source with date, and a note. The tables come from four separate check runs (hardware, data center and rates, Ollama and Hailo models, frontier models) and are included in full; the decisions based on them are listed first.

## Notes on methodology

- Apple does not publish TFLOPS values. The "tf" estimates are based on T. Zakharko's measurement of the GPU neural accelerators (approx. 1024 FP16 FLOPS per GPU core and clock, A19/M5); all Apple tf values are therefore "uncertain", but lie consistently approx. 15–35% below the theoretical estimate.
- For DGX Spark and RTX PRO 6000, NVIDIA only states FP4 sparsity TOPS; dense FP16 was derived via the fixed ratio FP4 sparse : FP16 dense (FP32 acc.) = 16 : 1 (according to the Blackwell white paper for RTX 5090: 3352 : 209.5).
- Apple power draw comes from the official "Power consumption and thermal output" pages (wall measurement, "Max" = CPU stress test, "Idle" = Finder). LLM inference load typically lies between the two values.
- Geizhals category pages block automated retrieval; prices come from the product pages (title line "from €", last price update 2026-10-11, 21:57) and from PCGH/3DCenter/ComputerBase.

Method:
- Ollama: model page, tag list and tag detail page (ollama.com/library/…); sizes as Ollama displays them (decimal GB, rounded). According to the blob hash, the default tags (without suffix) are each Q4_K_M, except nimble (Q8_0).

Linear-attention/Mamba states and sliding-window buffers (512 tokens) are constant and do not enter the per-token value.
- GGUF file sizes: Hugging Face file lists (bytes, converted to decimal GB).
- Hailo: the LLM list is not in the vision zoo (hailo-ai/hailo_model_zoo, which only covers classification/detection etc.), but in the separate repo hailo-ai/hailo_model_zoo_genai (docs/MODELS.rst, HEF links to v5.4.0; CHANGELOG up to v5.3.0; README badge HailoRT 5.4.0).

## Main deviations (summary)

1. granite4.2:30b, KV Bytes/Token: 196,608 → 262,144 (64 layers × 8 KV heads × 128 × 2 × 2). Our value corresponds to 48 layers.
2. qwen3.8:27b and clef, KV Bytes/Token: 131,072 → 65,536. Only 16 of the 64 layers are full attention (4 KV heads, head dim 256); the 48 Gated DeltaNet layers have a constant state. For the 9B sibling model (ornith 9b, nimble), our value of 32,768 is correct by the same logic.
3. laguna-xs-2.1, KV Bytes/Token: 20,480 → 40,960 at FP16 (10 global layers × 8 KV heads × 128). Our value corresponds to FP8 (Poolside uses an FP8 KV cache), but is inconsistent with laguna-s-2.1, where we assume FP16 (49,152).
4. laguna-s-2.1, Q4_K_M: for the tag q4_K_M/latest, Ollama currently delivers 96 GB (mixed quantization with BF16 experts in the last 8 blocks), while the Ollama README states 75 GB and a true Q4_K_M on Hugging Face is 73 GB. Our 75 matches the README/HF, not the actual Ollama download.
5. nimble, Ollama tag: 9.3 → 9.5 GB (current version, Q8_0). Minor.
6. Qwen3-VL 2B (Hailo): the quantization label is A16W4, not INT4/A8W4; the size of 2.18 GB is correct.
7. Context lengths (ours "–"): granite 131,072; ornith/qwen3.8/laguna-xs 262,144; nemotron 1,048,576 (Ollama GGUF); laguna-s 262,144 (Ollama GGUF tags) or 1,048,576 (architecture).

## Methodological notes

- GGUF sizes: sum of the shard sizes according to the HF API (`https://huggingface.co/api/models/<repo>/tree/main?recursive=true`), in decimal GB (10⁹ bytes) – this is also how Hugging Face displays them. In GiB the values are about 7% smaller (e.g. GLM-5.3-Flash UD-Q4_K_XL 186.0 GiB).
- For DeepSeek V4 (expert_dtype fp4) and Kimi K3 (MXFP4 MoE), Q8_K_XL is only slightly larger than Q4_K_XL because the expert weights are already natively 4-bit; there Q8_K_XL is "lossless".
- KV calculation: for hybrid models (GLM-5.3-Flash, Qwen3.5/3.8, Kimi K3) only the cache of the full/sparse attention layers grows with the context; the linear-attention/KDA layers hold a constant state per sequence. For DeepSeek V4 the paper (arXiv 2606.19348) describes block compression of 4:1 (CSA) and 128:1 (HCA) plus a sliding window of 128 tokens; the stated range is an estimate from config.json and the paper, not a measurement in llama.cpp.
- Speculative decoding: both figures stored on our side (DeepSeek V4 Flash "Draft n=3, ×1.9"; GLM-5.3-Flash "MTP n=2, ×1.48") appear in the Unsloth documentation, verbatim or by calculation respectively. The DeepSeek figure applies to the 0731 version with the DSpark drafter (≈10 GB of additional memory), not to the April preview model.
- Not found: Mistral Large 4 (API preview only; weights announced for the end of October 2026). For DeepSeek V4 Pro an unsloth GGUF exists only for the 0813 version; for DeepSeek V4.1 Flash (Sep 2026, 552B) there is no unsloth GGUF yet.
